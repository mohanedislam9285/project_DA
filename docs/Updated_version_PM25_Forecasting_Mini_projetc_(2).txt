PM2.5 Forecasting  
1. Context and motivation 
PM2.5 refers to fine particulate matter that can affect human health. Forecasting daily surface PM2.5 
from historical air-quality, satellite/reanalysis, and meteorological data can support air-quality 
monitoring. A model with a low error on one split, however, may not generalize to future dates or 
unseen stations. 
The project compares forecasting methods along three complementary dimensions: 
 Predictive performance: how close predictions are to observed PM2.5 concentrations. 
 Robustness: how performance changes across data partitions, training-set sizes, and reasonable 
experimental choices. 
 Explainability stability: whether the features identified as important remain similar across folds, 
validation schemes, and models. 
All groups must use the shared protocol and report limitations. The aim is not simply to find the lowest 
error, but to recommend a model whose performance is reliable and whose computational cost and 
explanations are understood. 
2. Learning objectives 
By completing the project, students should be able to: 
 Build a reproducible supervised-regression pipeline for daily PM2.5 forecasting. 
 Audit, explore, clean, and prepare spatiotemporal data while preventing data leakage. 
 Compare models using appropriate error metrics and time-aware and location-aware validation. 
 Analyze robustness, prediction errors, feature importance, and computational cost. 
 Conduct controlled ablation and statistical comparisons, then communicate findings in a scientific 
report and oral presentation.

5. Experimental protocol 
5.1 Data exploration and preparation 
 Describe the dataset, target, units, temporal coverage, spatial coverage, and variables. 
 Summarize numerical variables using minimum, maximum, mean, standard deviation, quartiles, 
skewness, and kurtosis. Count categories for relevant identifiers. 
 Visualize key variables (PM2.5, AOD, NO₂, CO, O₃, temperature, pressure, and wind): use 
histograms, boxplots, and suitable categorical plots. 
 Quantify missingness and inspect potential outliers using domain knowledge, boxplots, IQR, z-
scores, Isolation Forest, or LOF as appropriate. 
 Remove rows with missing PM2.5 or documented invalid sentinel values PM2.5 ≤ 0 or PM2.5 ≥ 500 
before EDA and splitting; report counts removed. 
 Inspect duplicates using all columns and key fields (date, latitude, longitude, station ID). 
 Analyze relationships using Pearson/Spearman correlations, identify highly correlated predictors (|r| 
> 0.9), and consider VIF or PCA where useful. t-SNE/UMAP are exploratory visualizations, not 
proof of predictive value. 
 Study PM2.5–predictor relationships, including possible seasonal/station differences and the 
influence of meteorology on PM2.5–AOD associations. 
 Describe the skewed target distribution, seasonal variation, and the proportions above 25 and 50 
µg/m³. Consider what this means for RMSE, MAE, and extreme-event errors. 
EDA outputs: save numerical summaries and temporal diagnostics in Exploratory_Data.csv and 
Exploratory_temporal.csv (use consistent filenames throughout the project).

5.2 Time-series exploration 
Decision gate: determine whether temporal validation and lag-based features are appropriate from the 
timestamp quality, temporal dependence, and intended forecasting scenario. 
 Check timestamp regularity, daily sampling, missing dates, duplicate timestamps, and irregular 
observations per station. 
 Explore autocorrelation and stationarity using ACF/PACF and, where appropriate, Ljung–Box and 
ADF tests. 
 Examine target drift across months and years using median, IQR, and high-concentration frequency. 
 Identify daily, monthly, and seasonal patterns in PM2.5 and atmospheric predictors. 
 Explore lead–lag relationships between PM2.5 and AOD, NO₂, CO, O₃, wind, and temperature. 
5.3 Preprocessing without data leakage 
All learned transformations must be fitted on each training fold only. Use a scikit-learn Pipeline, or an 
imbalanced-learn Pipeline when resampling is required. Keep validation data separate from training 
operations and reserve the final test period for final evaluation. 
5.3.1 Missing values 
 Numerical variables: use median imputation by default; consider KNNImputer only when its 
assumptions and stability are justified. 
 Categorical variables: use mode imputation or an explicit “missing” category. 
 For real-time forecasting, use forward-fill only when operationally justified; avoid backward-fill or 
interpolation that uses future information. 
 For Sentinel-5P NO₂, CO, and O₃, use training-fold median imputation plus a missingness indicator 
for each column. Do not forward-fill these columns across days. 
 Report missingness by variable and, for NO₂/CO/O₃, by month and station. Use KNN imputation for 
these variables only if the correlation structure is stable across training folds. 
5.3.2 Scaling and feature selection 
 Use StandardScaler or RobustScaler for scale-sensitive models such as SVR, KNN, neural networks, 
and PCA. Tree-based models generally do not need scaling. 
 Fit scaling and feature-selection steps within each training fold. 
 Possible feature-selection methods: filter methods (ANOVA F-test or mutual information), wrapper 
methods (RFE), and embedded methods (L1 regularization or tree importance). 
 Record selected features and their number; never select features using the full dataset or test labels. 
5.3.3 Outliers 
 Preserve extreme but plausible PM2.5 observations; distinguish measurement errors from genuine 
pollution episodes. 
 If thresholds are learned from data, estimate them on training data and apply them unchanged to 
validation/test data. 
 Compare MAE, RMSE, and R² with and without the chosen outlier treatment on the same held-out 
data.

5.3.4 Temporal preprocessing and feature engineering 
 Validate timestamps and create a regular daily timeline separately for each station. Decide which 
stations to retain before splitting. 
 Match station records to corresponding GEE IDs using date and nearest latitude/longitude 
(approximately 0.25°), and never mix stations or IDs. 
 Create lags, rolling statistics, differences, rates of change, and calendar features only when justified 
by Section 5.2. 
 Use past PM2.5 values only for forecasts at least one day ahead; exclude them from same-day 
nowcasting to prevent target leakage. 
 Do not calculate lags across multi-day gaps. All imputations and temporal features must use past 
information only.

6.3 Fair comparison rules 
 Use identical folds and a comparable hyperparameter-search budget for every model. 
 Use RMSE as the primary model-selection metric; also report MAE, R², and MAPE where it is 
meaningful. MAPE can be unstable when observed values are near zero, so explain any use or 
omission. 
 Report each metric as mean ± standard deviation across folds and provide 95% bootstrap confidence 
intervals. 
 Do not use residual or quantile calibration in the main comparison; it may be an optional extension 
after initial model selection. 
 Log training time, total search time, inference time (with prediction sample size), hardware, and 
serialized model size. Report parameter counts for deep/hybrid models and tree/leaf counts where 
meaningful. 
6.4 Robustness analysis 
6.4.1 Partition robustness 
 Store fold-level results for temporal, spatial, and diagnostic random CV in results.csv. 
 For each model and scheme, report mean, standard deviation, 95% bootstrap CI, and coefficient of 
variation where interpretable. 
 Report optimism gaps: random K-Fold RMSE − temporal RMSE, and random K-Fold RMSE − 
spatial-CV RMSE. Interpret large differences as evidence that random splitting may be optimistic. 
 Use paired comparisons on the same folds where appropriate; acknowledge the limited power of 
tests based on only five folds. 
6.4.2 Sensitivity to training-set size 
 Train on 10%, 25%, 50%, 75%, and 100% of the development data, respecting chronological order; 
validate on the next temporal block. 
 Keep the final future test period untouched. If resources are limited, evaluate the three best models 
per group instead of all models and state this restriction in advance. 
 Plot RMSE against training-set size. Define the plateau as the point beyond which more data 
improves RMSE by less than 5%. 
6.4.3 Spatial and temporal generalization 
 Use five-fold spatial GroupKFold by station ID, or spatial clusters based on coordinates, when 
metadata support this analysis. 
 Report metrics and bootstrap confidence intervals by spatial fold; map station-level errors when 
possible. 
 Exclude IDs and coordinates as predictive inputs in the spatial-generalization experiment. 
 Evaluate the best model from each group on an independent future year (for example, 2025, if it is 
available and excluded from all CV folds); report monthly RMSE to reveal seasonal weaknesses.

6.5 Hyperparameter optimization 
        To ensure fair comparisons and reproducibility, all hyperparameter optimisation must be performed 
exclusively on the training folds of the cross-validation scheme, never on the validation or test sets. 
For each model group, follow these steps: 
 Define the search space: Specify the hyperparameters, candidate values, and ranges in the table 
below. The search space must be predefined to prevent data-dependent tuning. 
 Select an optimisation strategy: Choose the method according to the size and computational 
cost of the search space (see table below). 
 Run the optimisation: Use a fixed computational budget and a fixed random seed (e.g., 
random_state=42) to ensure reproducibility. The computational budget must be comparable 
across models (e.g., a maximum of 50 model evaluations). 
 Retain the top three configurations: Select the three best hyperparameter setups found during 
tuning. They must use different parameter values (not just different random seeds). 
 Test robustness: Take the top three configurations and slightly vary their key parameters (one 
step above and below) to see if the model remains stable or if its performance drops 
significantly. 
 Report the results: Include the best configuration, the performance of the top three, the 
robustness verdict, and the final selected hyperparameters in hyperparameters.csv.

6.7 Explainability and explanation stability 
6.7.1 Global feature importance 
 Mandatory: compute permutation importance on validation folds for all models. 
 Optional: apply SHAP to one or two representative models; report runtime and compare SHAP 
rankings with permutation importance. 
 For linear models, report standardized coefficients and, where feasible, bootstrap confidence 
intervals. For deep/hybrid models, permutation importance is the common required method. 
6.7.2 Ranking stability 
 Compare feature rankings across folds, across validation schemes, and across models within the 
same group. 
 Use Spearman rank correlation for full rankings and Jaccard overlap for top-3/top-5 features. 
 As practical reference thresholds, report whether fold-level rho exceeds 0.8 and whether top-5 
overlap across schemes exceeds 60%; explain cases below these thresholds. 
6.7.3 Local explanations 
 Select representative days with low (<10), medium (10–25), high (25–50), and extreme (>50 µg/m³) 
PM2.5, plus the day with the largest prediction error. 
 Compare the top three models on the same cases. Use SHAP contributions if available; otherwise 
describe observed feature values and prediction errors without claiming causal explanations.

Use permutation importance for all models and treat SHAP as an optional extension. Recommend one

7. Statistical analysis 
7.1 General principle 
Compare models using paired results from the same folds and validation scheme. Fold scores are 
dependent and only five folds provide limited statistical power; avoid interpreting a single p-value as 
conclusive evidence. 
7.2 Performance calculation 
 For every model, metric, and validation scheme, retain the score from each of the five folds. 
 Report mean ± standard deviation and a 95% bootstrap confidence interval. 
 Calculate the two optimism gaps defined in Section 6.4.1. 
7.3 Statistical tests 
 Primary comparison: paired Wilcoxon signed-rank test on fold-level errors from the same folds. 
 Correct multiple pairwise comparisons using Holm–Bonferroni. 
 Complementary analyses: bootstrap confidence intervals for mean differences and permutation tests 
(10,000 permutations where computationally feasible). 
 Report corrected p-values, an effect size (for example, Wilcoxon r), and the practical size of the 
difference. Treat p < 0.05 after correction as the significance threshold. 
7.4 Reporting 
Save fold-level results for every model and validation scheme in results.csv, and pairwise summaries in 
comparisons.csv. 
 Primary report: mean ± standard deviation, 95% CI, mean difference with CI, effect size, and 
corrected p-value. 
 Complementary report: bootstrap CI for the mean difference and permutation-test result. 
 Discuss both statistical evidence and practical importance; with five folds, explicitly acknowledge 
uncertainty and low test power.

8. Ablation study 
8.1 Purpose and scope 
Ablation tests how feature families, preprocessing choices, and validation schemes affect results. It is an 
analysis of the existing models, not an invitation to add new models. 
Use these reference models: ElasticNet, SVR-RBF, XGBoost, SARIMAX, LSTM, CNN-LSTM, and 
Stacking. Use temporal CV (five folds, one-day gap) as the primary scheme. Use spatial grouped CV for 
feature-group ablation when metadata permit. 
8.2 Feature-group ablation 
Starting from the full feature set, remove one family at a time: 
 AOD. 
 NO₂/CO/O₃. 
 Meteorological variables. 
 Calendar variables. 
 Lag and rolling features. 
For each reference model, report the RMSE difference between the ablated and full-feature versions, 
with a confidence interval across folds. Define ΔRMSE = RMSE(ablated) − RMSE(full). Positive values 
indicate that removing the feature family hurt performance; values near zero suggest limited 
contribution; negative values suggest that removal improved performance. 
8.3 Preprocessing ablation 
 Compare median imputation with KNNImputer for NO₂/CO/O₃ only if the stability condition in 
Section 5.3.1 is met. 
 Compare models with and without missingness indicators. 
 Compare raw-target training with log1p-transformed-target training. 
 Evaluate every variant on the original PM2.5 scale (µg/m³) and report ΔRMSE. 
8.4 Validation-scheme ablation 
For each reference model, compare temporal CV, spatial CV, and diagnostic random K-Fold. Report 
random K-Fold RMSE − temporal RMSE and random K-Fold RMSE − spatial-CV RMSE. Large gaps 
can indicate optimistic random-split estimates caused by temporal or spatial similarity. 
8.5 Reporting and reproducibility 
 Provide one table per ablation axis, with models as rows and variants as columns. 
 Report RMSE as mean ± standard deviation across folds and include bootstrap CIs where 
appropriate. 
 Write a short interpretation identifying useful or redundant components, affected model families, and 
the validation scheme.
